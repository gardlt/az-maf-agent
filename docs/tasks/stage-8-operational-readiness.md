# Stage 8 tasks — Operational readiness and assurance

## Ordered tasks

- [ ] **S8-01 — Freeze the readiness scope and gate inventory.** Map every item to Stage 1/5/7 or architecture review R01–R10, identify the target environment/release and assign real accountable owners, dates, reviewers and decision authority. Record missing permissions/configuration and distinguish blockers from proposals. Deliver `readiness-scope.md`. No owner or approval is implied by this task.
- [ ] **S8-02 — Integrate Stage 7 closure.** Depends on S8-01 and the Stage 7 controller/resource enforcement work. Link verified individual-agent quarantine, cached/exfiltrated token denial, direct-MI/alternate-credential denial, live A/B isolation, outages, repeated alerts, escalation and explicit recovery evidence. Directory disable alone cannot pass. Preserve the prior negative drill findings; do not implement a competing controller under Stage 8.
- [ ] **S8-03 — Prove hosted isolation and races.** Depends on S8-01 and available authorized A/B test principals/resources. Exercise two real users and agents with synthetic owned records, positive owner controls and foreign read/write/reset/cancel/receipt denial. Repeat across replicas/revisions, concurrent requests, resets, retries and delayed completions. Verify resource effects, no data leakage/history resurrection, no lost reservations and no counter reset. Deliver `hosted-isolation.md` and `concurrency-results.json`.
- [ ] **S8-04 — Close the final network gate.** Depends on S8-01 and the separately approved Stage 5 topology/cutover. Verify authorized traffic, blocked unapproved destinations, reachable-host forbidden-operation denial, redirect/endpoint escapes, internal MCP ingress/auth and no public API bypass in that exact topology. Include DNS/identity/configuration/monitoring dependencies and controller availability. Deliver `network-acceptance.md`; historical temporary-network evidence is insufficient.
- [ ] **S8-05 — Freeze and implement grounding evaluation.** Can run alongside S8-02–04 after S8-01. Define versioned public/synthetic movie facts, expected source IDs/fields, source-citation behavior and rules for unsupported claims/abstention. Freeze quality thresholds and grader methodology before scoring. Cover missing, ambiguous, irrelevant, stale and poisoned sources across routine/stronger routes; separate retrieval, factual correctness and faithful source use. Preserve the existing benign-success floor and zero forbidden effects. Deliver `grounding-policy.md`, fixture/grader hashes and `grounding-results.json`.
- [ ] **S8-06 — Automate acceptance orchestration.** Depends on S8-01; integrate the S8-02–05 suites as they become available. Reuse current scripts behind one documented local/CI entry point with explicit local/hosted/destructive modes, environment/identity allowlists, concurrency limits, existing budget enforcement, timeouts and guaranteed cleanup/restoration. Secrets and raw payloads must not enter artifacts. Always retain failed/skipped/blocked results, exact versions and command/config metadata; validate doc links and evidence hashes. No silent budget reset or unsafe automatic identity drill on every PR. Deliver `acceptance-workflow.md` and a reproducible release evidence manifest.
- [ ] **S8-07 — Rehearse operations and promotion.** Depends on S8-01 and applicable Stage 5/7 controls; may prepare runbooks in parallel. Rehearse provider/control/telemetry outages, alert delivery/escalation, credential rotation, schema-compatible rollback, cleanup/deletion and explicitly authorized recovery without stale work or lost accounting. Freeze measurable availability/latency/containment/recovery objectives and evidence-retention/cost/capacity bounds. Inspect actual GitHub environment approvals, protections, OIDC subjects and scoped release roles for stage/prod. Record named responders and review outcomes in `operations-rehearsal.md` and `promotion-review.md`.
- [ ] **S8-08 — Add repository governance and newcomer guidance.** Can run in parallel after S8-01. Obtain the maintainer's license choice before adding a license; add contribution/testing guidance, a real security-reporting route, verified code owners and usable issue/PR templates. Verify a fresh offline setup and document the separate operator/bootstrap/cloud prerequisites without embedding real secrets. Deliver `repository-readiness.md` with links and a newcomer smoke result.
- [ ] **S8-09 — Review a complete readiness package.** Depends on S8-02–08, the selected S8-10–20 extensions below and all applicable earlier release gates. Record conditional exclusions explicitly; do not silently skip them. Re-run proportional acceptance against the exact release; record pass/fail/blocked status, named reviewers, unresolved risks and any explicitly authorized bounded risk dispositions. Update roadmap, architecture evidence/gap registers and operator docs. Deliver `acceptance-review.md`. Do not equate a checklist, local test pass or skipped hosted test with approval.

## Additional application features and security tasks

Priority: design streaming/progress and durable workflows first, alongside injection/exfiltration fixtures. Apply S8-01 scope/version/owner decisions to every extension. S8-06 must collect the selected extensions' evidence before S8-09 review. These are planned tasks, not implementation authorization or completed features.

- [ ] **S8-10 — Streaming responses and safe progress.** Depends on S8-01 and existing run/session controls. Add owner-authorized progress events and bounded answer streaming with run/event identifiers, disconnect/reconnect semantics, backpressure and cancellation. Check policy/quarantine and output rules before each published chunk; do not expose hidden reasoning, raw tool payloads, private memory or credentials. Verify foreign subscribers cannot observe/replay events, cancellation stops later output, slow clients cannot exhaust workers and partial answers remain visibly incomplete. Already delivered chunks cannot be retracted. Deliver `streaming-results.md`.
- [ ] **S8-11 — Durable pause/resume workflows.** Depends on S8-01, established shared-session/accounting fences and selected checkpoint-storage/retention policy; can be designed alongside S8-10. Persist only reviewed bounded checkpoint data/references, not automatic copies of private context. Resume after restart using owner binding, policy/quarantine generation and current permissions; expired/revoked work fails closed. Tool retries require idempotency or explicit unknown-outcome reconciliation, never an exactly-once assumption. Test duplicate resumes, competing replicas, reset/delete/revocation races, pause expiry and budget preservation. Deliver `workflow-policy.md` and `workflow-results.json`.
- [ ] **S8-12 — Source-backed answer presentation.** Extends S8-05 rather than adding a second grounding evaluator. Return validated source identifiers/links, retrieval time and relevant fields used for the answer. Distinguish supported facts from suggestions, indicate unavailable/conflicting evidence and abstain where the frozen policy requires it. Verify citations support the associated claim, redirects/generated URLs cannot escape the approved source origin and both routes behave consistently. Deliver `source-response-results.json` and integrate into `grounding-results.json`.
- [ ] **S8-13 — Real consequential-action approval (conditional).** Only after a concrete action domain, permitted resources and approvers are explicitly selected; retain existing simulation-only behavior otherwise. Depends on S8-11, S8-18 and the action's authorization design. Extend existing approval primitives into an exact action preview bound to tenant, user, agent, resource, operation, argument digest, policy/configuration version, expiry and single-use receipt. Test replay, changed arguments, confused deputy, revocation, duplicate delivery and ambiguous completion. Approval never grants a forbidden movie write or bypasses normal permission. Use a harmless fixture until live effects are separately approved. Deliver `action-approval-results.md` or an explicit deferred-scope decision.
- [ ] **S8-14 — Controlled specialist-agent delegation (conditional).** Require a demonstrated task benefit before adding agents. Depends on S8-02, S8-03, S8-11 and S8-18. Give each independently containable agent a distinct identity and bounded capability/task contract; do not inherit parent credentials or authority. Bound delegation depth, fan-out, time and aggregate cost; prohibit unauthorized re-delegation. Test malicious peer output, forged handoff/completion, cross-agent data access, authority escalation, cycles, child cancellation and one-agent quarantine with others unaffected. Deliver `delegation-results.md` or a reviewed deferral. No new sub-agent implementation is implied by this task list.
- [ ] **S8-15 — Indirect prompt-injection and context-poisoning defenses.** Depends on S8-01 and existing trust boundaries. Mark user text, retrieved movie descriptions, tool output, reviewed-skill content and recalled data with their actual trust/provenance; none can authorize actions or rewrite policy. Add direct/indirect, multi-turn, encoded, conflicting-instruction, summary/memory poisoning and tool-output attack fixtures. Evaluate an optional detection service against pinned support, cost and privacy requirements before selecting it; classifiers supplement deterministic authorization. Require zero forbidden effects and separately measure benign false positives with frozen criteria. Deliver `injection-results.json`.
- [ ] **S8-16 — Data-loss prevention at context and egress boundaries.** Depends on S8-01 and the data/resource inventory. Define permitted data classes and destinations for model context, tools, answers, streaming, telemetry and evidence. Test synthetic secrets/foreign-user canaries, transformed/encoded strings and attacker links without real private data. Minimize/redact/block as policy requires; detection uncertainty or outage must follow the predeclared safe behavior. Record coverage limits and false positives; do not claim a regex or classifier guarantees non-disclosure. Deliver `data-egress-policy.md` and `dlp-results.json`.
- [ ] **S8-17 — Safe output validation and rendering.** Depends on S8-10/S8-12 for their respective output paths. Validate structured answers and sanitize Markdown/HTML for any selected renderer; disable dangerous URL schemes, executable content and unapproved remote images/automatic fetches. Prevent generated links from becoming an exfiltration or server-side request path; preserve the plain-text CLI contract. Test malformed/oversized/stream-fragmented output, injection across chunk boundaries, deceptive links and embedded external resources. Deliver `output-safety-results.md`.
- [ ] **S8-18 — Per-action authority and delegation binding.** Extends existing caller ownership and tool gates. Bind each permitted operation to tenant, user, Agent ID, resource, approved purpose and current policy; validate at the service boundary before effects. Agent authentication is not blanket authority to act for every user. Separate app-only permissions from any future user-delegated/on-behalf-of consent; select the flow explicitly before adding it. Test scope substitution, mismatched token audience, forged user headers, confused deputy, replay and approved-action argument/resource changes. Deliver `action-authority-results.json`.
- [ ] **S8-19 — Admission abuse and queue protection.** Depends on S8-01 and existing token/spend/concurrency limits. Add reviewed request-rate, queue-size, timeout and admission policies with tenant/user/agent attribution; do not conflate HTTP traffic limits with billable budgets. Test distributed replicas, unauthenticated floods, repeated reconnects/cancels, retry storms and queue starvation. Preserve retry hints, fair access and independent emergency-control availability; a limiter outage must not disable required containment. Deliver `abuse-admission-results.json` with frozen bounds and positive controls.
- [ ] **S8-20 — Tool and delegation contract change control.** Extends the existing pinned MCP schemas and reviewed skill hashes. Version tool origin/server identity, discovery metadata, schema, effective permissions and behavior; require review before accepting capability expansion or changed semantics. Reject unapproved drift at startup/refresh and prevent cached approvals from authorizing a new contract version. Test tool description poisoning, same-name replacement, schema changes, injected credentials and permission expansion. Include handoff-contract changes if S8-14 is selected. Deliver `tool-change-results.md`.

Reference design inputs, to re-verify against selected versions during implementation: [Agent Framework human-in-the-loop workflows](https://learn.microsoft.com/en-us/agent-framework/workflows/human-in-the-loop), [workflow checkpoints](https://learn.microsoft.com/en-us/agent-framework/workflows/checkpoints), [Microsoft Prompt Shields](https://learn.microsoft.com/en-us/azure/ai-services/content-safety/concepts/jailbreak-detection), and [OWASP agentic risks](https://genai.owasp.org/2025/12/09/owasp-top-10-for-agentic-applications-the-benchmark-for-agentic-security-in-the-age-of-autonomous-ai/).

## Acceptance gates

- [ ] Earlier Stage 1/5/7 dependencies have closure evidence or an explicit reviewed disposition for the exact requested release; their historical checklists remain intact.
- [ ] Real hosted identity/user isolation, race handling and final-topology network denials pass with independent effect checks and positive controls.
- [ ] Grounding evaluation uses frozen fixtures/thresholds, records both routes and failures, and measures source faithfulness and abstention separately from tool success.
- [ ] A repeatable acceptance workflow preserves evidence and failures, respects budgets/permissions, redacts credentials/private data and validates documentation/integrity.
- [ ] Rotation, rollback, outage, incident escalation and recovery rehearsals meet predeclared objectives; real owners and stage/prod promotion boundaries are verified.
- [ ] License, contribution, security reporting and code ownership are selected/verified by maintainers; a fresh contributor can reproduce offline setup.
- [ ] Selected streaming/workflow/source features preserve owner scope, cancellation, quarantine, expiry and shared accounting across resumes/reconnects.
- [ ] Injection/exfiltration, unsafe rendering, per-action authority, admission abuse and tool-change suites pass with zero forbidden effects and documented coverage/false-positive limits.
- [ ] Consequential actions and multi-agent delegation are either explicitly approved and tested within their chosen scope, or documented as deferred with no authority added.
- [ ] Final review states exactly what is accepted, by whom, for which environment/release and with which limitations. No blanket production or universal grounding claim is made.

Implementation/deployment is not authorized by merely adding this plan. Keep cloud privilege, cost and disruptive-test approvals tied to the actual changes; do not ask again for an action already explicitly approved within its original scope.
