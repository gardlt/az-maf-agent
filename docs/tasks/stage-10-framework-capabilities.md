# Stage 10 tasks — Native framework capability adoption

Status: **planned; no migration or acceptance executed**, 2026-10-20.

[Stage guide](../stages/stage-10/README.md) · [Validation/evidence](../stages/stage-10/validation/README.md) · [Roadmap](README.md)

## Ordered tasks

- [ ] **S10-01 — Freeze the SDK baseline and equivalence contract.** Inventory the actual pinned Python exports/signatures and agent lifecycle, custom client/transport, shared sessions, controls, approvals and FastMCP integration. Map candidates to Stage 8 S8-10–20 and Stage 9 sensitive-data tasks. Define measured goals, required security invariants, fixture baselines, compatibility risks, dependency decisions and rollback before refactoring. Deliver `framework-inventory.md` and `equivalence-policy.md`; the earlier import check alone is not acceptance.
- [ ] **S10-02 — Evaluate native middleware.** Depends on S10-01. Prototype agent/chat/function middleware for validation/redaction/audit hooks with fixture providers. Verify ordering relative to history/context, tool execution and persistence, including exceptions, streams and cancellation. Ensure every dispatch remains gated and required audit precedes effects; retain service/resource authorization outside the model runtime. Compare code complexity and behavior against current wrappers, and document adopt/retain decisions. Deliver `middleware-results.json`.
- [ ] **S10-03 — Evaluate workflows and durable checkpoints.** Depends on S10-01/02 and Stage 8 S8-11 contracts. Build a bounded multi-step fixture that pauses/resumes after restart using current-owner, policy/quarantine generation and budget checks. Select hosted checkpoint storage/retention separately; local file/in-memory examples are not multi-replica durability. Test duplicate resume, unsafe/corrupt serialization, schema changes, expired/deleted records, competing replicas and unknown external outcomes. Prohibit unreviewed context copies and implicit exactly-once claims. Deliver `checkpoint-decision.md` and `workflow-framework-results.json`.
- [ ] **S10-04 — Integrate native approval events without changing authority.** Depends on S10-02/03 and existing approval contracts; real actions remain conditional under Stage 8 S8-13. Evaluate `ToolApprovalMiddleware` and workflow approval request/response behavior for a harmless fixture. Preserve independent principal/resource/argument/version binding, authorized approver, expiry, revocation, single use, persisted receipt and safe resume. Test forged approval, argument drift, replay, provider retries, cancellation and stale checkpoint approval. Deliver `approval-framework-results.json`; approval cannot enable a forbidden operation.
- [ ] **S10-05 — Evaluate native streaming and progress.** Depends on S10-02 and Stage 8 S8-10/S8-17 plus relevant Stage 9 output rules. Adapt the guarded client/provider only behind an explicit feature flag. Verify chunk filtering before publication, owner-only events, bounded queues/backpressure, disconnect/resume, usage reconciliation, refusal/errors and quarantine cancellation on both routes. Do not expose hidden reasoning, private tool payloads or unfiltered partial output. Delivered chunks cannot be retracted. Deliver `streaming-framework-results.json`.
- [ ] **S10-06 — Compare native MCP adapters with our guarded FastMCP path.** Depends on S10-01/02 and existing MCP identity/schema/egress controls. Evaluate native HTTP and stdio adapters using the same pinned read-only tools. Test explicit Entra Agent ID credential use without workload fallback, approved origin/audience, response/schema/size limits, redirects, reconnect cleanup, tool metadata drift and automatic invocation behavior. Prevent native discovery or automatic tool loops from bypassing budgets, permission, quarantine or audit. Replace code only where equivalent behavior is proven; retain wrappers otherwise. Deliver `mcp-adapter-comparison.md` and `mcp-framework-results.json`.
- [ ] **S10-07 — Evaluate orchestration/handoffs only if selected.** Depends on S10-03–06, Stage 7 hosted containment and Stage 8 S8-14/S8-18 contracts. Select a concrete specialist use case and assess sequential/concurrent/handoff patterns with separate agent identities. Bound depth/fan-out/time/aggregate spend, scoped messages and delegation authority. Test forged peer results, credential/identity substitution, malicious handoff instructions, child failure, parent cancellation and one-agent disable with other agents unaffected. Deliver `orchestration-decision.md` and, if selected, `orchestration-results.json`; an explicit deferral is valid and adds no agents.
- [ ] **S10-08 — Validate and review incremental adoption.** Depends on S10-02–06 and selected/explicitly deferred S10-07. Run equivalent local/authorized-hosted tests, both model routes, persisted-state compatibility, privacy-safe trace coverage, performance/cost comparison and rollback. Integrate artifacts into Stage 8 acceptance automation and Stage 9 data checks. Remove custom code only after its required behavior is covered; document retained components and limitations. Deliver `framework-adoption-review.md`, version/config/source hashes and release-scoped evidence. No blanket SDK migration or production approval is inferred.

## Acceptance gates

- [ ] API support is verified for pinned Python dependencies; any upgrade/provider change is separately reviewed and tested.
- [ ] Ownership, scoped identity, pinned tool contracts, budget/accounting, audit, quarantine and data-redaction invariants pass across all selected paths, including native automatic behavior.
- [ ] Resume/approval/streaming preserve current authority and cancellation; no stale work, approval replay, sensitive persistence or aggregate counter reset occurs.
- [ ] Native MCP dispatch does not widen origin, schemas, permissions, tool discovery or model-call authority; direct and alternate paths are covered.
- [ ] Adoption decisions are evidence-backed with measurable benefit, explicit non-adoptions and rollback; unnecessary multi-agent complexity is not introduced.
- [ ] Stage 8/9 feature/data acceptance remains independently satisfied. Framework hooks do not replace the Stage 7 independent controller/resource boundary.
